# Консольные примеры EMCL

Приложение читает Association LN `object_list` у прибора через **Wrapper/TCP** или **HDLC через TCP-шлюз** и сохраняет JSON. Настройки подключения и экспорта находятся в отдельном файле. Выполняются ассоциация и GET; значения остальных атрибутов не запрашиваются.

## Запуск

Скопируйте шаблон в `meter.local.json`, заполните адрес, порты и настройки ассоциации, затем запустите проект `EMCL.Examples` из IDE обычной командой **Run** без аргументов. Для командной строки из корня репозитория:

```sh
cp examples/EMCL.Examples/meter.example.json examples/EMCL.Examples/meter.local.json
dotnet run --project examples/EMCL.Examples -c Release
```

Без аргументов приложение использует `meter.local.json`, если он есть, иначе `meter.example.json`. Оба файла при сборке копируются рядом с приложением, поэтому рабочий каталог IDE не влияет на выбор настроек. После выгрузки в консоли печатается полный путь к JSON. Перед запуском измените конфигурацию под прибор; адрес, TCP-порт и Wrapper wPorts в шаблоне служат примером. `clientWrapperPort` и `serverWrapperPort` обозначают поля Wrapper, независимо от TCP-порта. Для шлюза HDLC задайте `"transport": "HdlcTcp"`, `hdlcClientAddress`, `hdlcServerLogicalAddress` и при наличии `hdlcServerPhysicalAddress`. Числа в этих полях задаются в десятичной форме.

Консоль показывает обмен: для Wrapper — полные DLMS APDU, для HDLC — кадры SNRM/UA/I/RR. Каждое сообщение получает номер, направление `TX`/`RX`, тип, длину и байты в hex. Например, `[0001] TX Aarq (42 bytes): 6028...`. При LLS/HLS содержимое AARQ и ACTION аутентификации скрывается; тип и длина остаются видны. Отдельные чтения TCP-потока не увеличивают счётчик.

Для другого файла конфигурации используйте `--config /path/to/meter.json`. Относительный `output.path` разрешается относительно каталога используемой конфигурации. При запуске из IDE это каталог сборки приложения. Например, `"path": "exports/meter.json"` создаст там подкаталог `exports`. В шаблоне `overwrite: true`, поэтому повторный запуск обновит JSON; задайте `false`, чтобы сохранять существующий файл. JSON записывается во временный файл и публикуется переименованием после завершения сериализации; отмена и ошибки не оставляют частичный целевой файл.

Профиль и версия Association LN задаются явно:

- `"profileId": "BlueBook.Ed16"`, обычно `"version": 3` для поддержанного профиля Blue Book;
- `"profileId": "Spodes.4"`, `"version": 1` для поддержанного профиля СПОДЭС.

Версия определяет интерпретацию прав и должна соответствовать реальной ассоциации прибора. При необходимости можно явно выбрать v1 при профиле Blue Book. `logicalName` выбирает объект ассоциации. `logicalDeviceId` и `associationId` — локальные имена каталога и снимка прав, не адреса подключения.

`connectTimeoutSeconds` ограничивает установление TCP-соединения, `requestTimeoutSeconds` — полный обмен, включая все GET-блоки. `limits` задаёт границы размера, вложенности, коллекций и числа блоков. Для чтения достаточно `"conformance": "Get, BlockTransferWithGet"`.

## Аутентификация

Для общедоступной ассоциации используйте `"authentication": "None"`, оставив все поля пароля равными `null`.

Для LLS задайте `"authentication": "Low"` и **ровно один** источник:

- `password` — текст, кодируемый UTF-8;
- `passwordHex` — точные байты в шестнадцатеричном формате без разделителей;
- `passwordEnvironmentVariable` — имя переменной окружения с текстовым паролем UTF-8.

Пример ссылки на переменную окружения:

```json
{
  "authentication": "Low",
  "password": null,
  "passwordHex": null,
  "passwordEnvironmentVariable": "EMCL_METER_PASSWORD"
}
```

Для HLS механизма `High` (AES-128 challenge-response, совместимого с Gurux) задайте `"authentication": "High"`, один из тех же источников 16-байтового секрета и включите `Action` в `conformance`, например `"Get, Action, BlockTransferWithGet"`. После AARE клиент вызывает `reply_to_HLS_authentication` у Association LN и проверяет ответ до открытия сессии. Другие HLS-механизмы, включая SHA-256 и GMAC, пока не реализованы.

Этот фрагмент помещается в секцию `association` полного конфига. Пароли не выводятся в консоль и не включаются в экспорт. Для пароля из цифр ASCII и UTF-8 дают одинаковые байты. Диагностика AARE печатается числом и именем, например `diagnostic=11 (AuthenticationMechanismNameNotRecognized)`; код 11 сам по себе не показывает, какой механизм требуется прибору.

## Содержимое экспорта

Корень содержит `schemaVersion` (сейчас 2), `exportedAtUtc`, `source`, согласованные параметры `negotiated`, `objectCount`, `objects` и `warnings`. `source` записывает выбранный транспорт и соответствующие ему адреса.

Если прибор возвращает абсолютно одинаковую запись `object_list` несколько раз, можно включить `"ignoreIdenticalObjectListEntries": true` в секции `association`. Экспорт сохранит уникальную запись и добавит предупреждение в `warnings`. Записи с одинаковым OBIS, но различающимся содержимым, по-прежнему вызывают ошибку импорта.

Для каждого объекта сохраняются:

- `obisCode` в форме `A.B.C.D.E.F`, `classId`, `classVersion`, `className`, `definitionKnown`;
- все объявленные прибором атрибуты и методы, дополненные членами известного точного определения класса;
- индексы, известные имена и DLMS-типы/теги атрибутов и параметров методов;
- `reportedByAssociation` и `definedByProfile`, чтобы отличать сведения прибора от метаданных библиотеки;
- `access.rawMode`, способ интерпретации `encoding`, читаемые имена `modes` и признаки `read`/`write` либо `invoke`;
- требования аутентификации v1 либо отдельные флаги защиты запроса/ответа v3, неизвестные биты `unknownBits`;
- селекторы атрибутов, объявленные ассоциацией.

`access: null` означает, что прибор не объявил права этого члена. Это отличается от объявленного режима запрета доступа `rawMode: 0`. Неизвестные классы, версии и дополнительные члены сохраняют идентификаторы и права; неизвестные имена и типы равны `null`. Имена-заглушки из импортера не выдаются за определения стандарта. Для атрибута CHOICE тип также может оставаться `null`.

Объекты сортируются по числовому OBIS-коду, члены — по знаковым индексам. Отрицательные пользовательские индексы сохраняются.

После сохранения программа пытается корректно завершить ассоциацию. Если прибор не подтверждает release, готовый JSON сохраняется, а диагностическое сообщение выводится в stderr. Основные ошибки чтения/импорта/записи возвращают код `1`, неверные аргументы — `2`, Ctrl+C — `130`.

## Локальные демонстрации

```sh
dotnet run --project examples/EMCL.Examples -c Release -- --demo
dotnet run --project examples/EMCL.Examples -- --help
```

`--help` выводит справку. `--demo` запускает прежние локальные примеры, включая клиентскую сессию с тестовым peer; подключение к прибору не требуется.
